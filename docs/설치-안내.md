## 1. Supabase 프로젝트 만들기

1. supabase.com 접속 → **New project**
2. 이름: `dawoong-gomin` (아무거나), 지역(Region): **Northeast Asia (Seoul)**

> ⚠️ **service_role key / secret key** 는 절대 사이트나 채팅에 붙여넣지 마세요. 이 안내에서는 쓸 일이 없어요.

## 2. 데이터베이스 만들기

터미널에서:

```bash
npx supabase login
```

```bash
npx supabase link --project-ref 프로젝트ref
```

```bash
npx supabase db push
```

`db push` 가 사연, 고민 동물, 방송 결과, 상담 후기, 도감 등 모든 표와 **접근 규칙(RLS)**, 오래된 기록 정리·자동 공개 작업까지 만들어요.

> 명령어가 어렵다면: Supabase 대시보드 → **SQL Editor** 에서 `supabase/migrations/` 폴더의 파일을 **이름 순서대로** 하나씩(`20261120000000_init.sql` → `20261121000000_broadcast_results.sql`) 통째로 붙여넣고 **Run** 해도 같아요.
>
> **이미 사이트를 쓰고 있었다면**: 코드를 새로 받은 뒤 `npx supabase db push` 만 다시 하면 새로 추가된 파일만 적용돼요. 기존 사연은 그대로 남아요.

## 3. 비밀 설정값(환경 변수) 넣기

서버 함수가 쓰는 비밀 값이에요. **사이트 코드에는 절대 들어가지 않고**, Supabase 서버에만 저장돼요.

```bash
npx supabase secrets set ADMIN_INITIAL_PASSWORD="처음-쓸-관리자-비밀번호"
```

```bash
npx supabase secrets set ANTHROPIC_API_KEY="sk-ant-여기에-키"
```

(선택) AI 모델 바꾸기. 비워두면 `claude-opus-5-5` 를 써요.

```bash
npx supabase secrets set AI_MODEL="claude-opus-5-5"
```

> 명령어 대신 대시보드에서: **Edge Functions → Secrets** 에서 이름과 값을 넣어도 돼요.

| 이름 | 꼭 필요? | 설명 |
|---|---|---|
| `ADMIN_INITIAL_PASSWORD` | 필수 | 처음 관리자 로그인 비밀번호. 처음 로그인하면 암호화(해시)되어 DB에 저장되고, 그 뒤로는 관리자 페이지에서 바꿔요. |
| `ANTHROPIC_API_KEY` | 권장 | Claude API 키. 사연을 보내는 순간 사연을 읽고 고민 동물 결과를 만들어요. 없거나 AI 가 늦으면(40초) "기본 동물 16종" 중 하나로 결과가 나와요. |
| `AI_MODEL` | 선택 | 기본 `claude-opus-5-5`. 비용을 줄이고 싶으면 `claude-sonnet-5-5` 같은 다른 모델 이름으로 바꿀 수 있어요. |

`SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY` 는 Supabase 가 자동으로 넣어주니 따로 넣지 마세요.

## 4. 서버 함수 올리기

```bash
npx supabase functions deploy public admin obs --no-verify-jwt
```

- `public`: 사연 제출(+ 고민 동물 결과), 내 사연 조회, 사연 옮기기/삭제, 탈퇴
- `admin`: 관리자 페이지 (비밀번호 확인, 사연 관리, AI 호출 등)
- `obs`: OBS 방송 카드

> `--no-verify-jwt` 는 "로그인 확인을 함수 안에서 직접 한다"는 뜻이에요. (관리자 비밀번호, 비밀 코드, OBS 키를 함수가 직접 검사해요.)

## 5. 로그인 설정 (카카오 · 구글)

### 5-1. 공통: 사이트 주소 등록

Supabase 대시보드 → **Authentication → URL Configuration**

- **Site URL**: 사이트 주소 (예: `https://dawoong-gomin.pages.dev`) — 6단계에서 정해져요. 먼저 6단계를 해도 돼요.
- **Redirect URLs** 에 추가: `https://dawoong-gomin.pages.dev/auth/callback`

**Authentication → Providers → Email** 은 **꺼두세요.** (이 사이트는 이메일 로그인을 쓰지 않아요.)

### 5-2. 카카오

1. developers.kakao.com → **내 애플리케이션 → 애플리케이션 추가하기**
2. **앱 키** 의 **REST API 키** 를 복사 → 이게 Client ID
3. **카카오 로그인** → 활성화 ON
4. **카카오 로그인 → Redirect URI** 에 `https://프로젝트ref.supabase.co/auth/v1/callback` 등록
5. **카카오 로그인 → 보안 → Client Secret** 코드 생성, 활성화 → 이게 Secret
6. **동의항목**: 닉네임(필수). 이메일은 쓰지 않아요.
   - Supabase 가 이메일을 요청해서 오류(KOE205)가 나면, 카카오 동의항목에서 **카카오계정(이메일)** 을 "선택 동의"로 켜주세요. (사이트는 이메일을 따로 저장하지 않아요)
7. Supabase → **Authentication → Providers → Kakao** 켜고 Client ID / Secret 붙여넣기
   - **Allow users without an email** 이 보이면 켜주세요.

### 5-3. 구글

1. console.cloud.google.com → 프로젝트 만들기
2. **API 및 서비스 → OAuth 동의 화면** 설정 (외부, 앱 이름 "다웅 고민 사연함")
3. **사용자 인증 정보 → 사용자 인증 정보 만들기 → OAuth 클라이언트 ID → 웹 애플리케이션**
4. **승인된 리디렉션 URI**: `https://프로젝트ref.supabase.co/auth/v1/callback`
5. 만들어진 **클라이언트 ID / 클라이언트 보안 비밀** 을 Supabase → **Providers → Google** 에 붙여넣기

> 치지직 로그인은 나중에 같은 방식(Supabase 의 로그인 방법 추가)으로 붙일 수 있게 만들어 두었어요.

## 6. 사이트 올리기 (Cloudflare Pages)

1. dash.cloudflare.com → **Workers & Pages → Create → Pages → Connect to Git**
2. 이 GitHub 저장소 선택
3. 빌드 설정
   - **Root directory**: `web`
   - **Build command**: `npm run build`
   - **Build output directory**: `dist`
4. **Environment variables** 에 추가

| 이름 | 값 |
|---|---|
| `VITE_SUPABASE_URL` | 1단계의 Project URL |
| `VITE_SUPABASE_ANON_KEY` | 1단계의 Publishable key (anon key) |
| `NODE_VERSION` | `20` |

5. **Save and Deploy** → 몇 분 뒤 `https://프로젝트이름.pages.dev` 주소가 생겨요.
6. 이 주소를 5-1 의 Site URL / Redirect URLs 에 넣었는지 다시 확인해요.

> 이 두 값(URL, Publishable key)은 공개되어도 괜찮은 값이에요. 데이터는 DB 접근 규칙이 지켜요.
> 도메인을 사고 싶다면 Cloudflare Pages → **Custom domains** 에서 연결하면 되고, 5-1 주소도 같이 바꿔주세요.

## 7. 처음 관리자 로그인

1. `https://사이트주소/admin` 으로 들어가요. (사이트 메뉴에는 링크가 없어요)
2. 3단계에서 정한 `ADMIN_INITIAL_PASSWORD` 를 입력
3. 들어가면 **설정 → 비밀번호 바꾸기** 에서 새 비밀번호(8자 이상)로 바꾸는 걸 추천해요.
   - 바꾸면 다른 기기의 관리자 로그인은 모두 풀려요.
   - 바꾼 뒤에는 `ADMIN_INITIAL_PASSWORD` 값은 더 이상 쓰이지 않아요.

로그인은 12시간 유지돼요. 공용 PC 에서는 **"이 기기 기억 안 함"** 을 체크하면 브라우저를 닫을 때 로그아웃돼요.
비밀번호를 5번 연속 틀리면 10분 동안 잠기고, 틀린 기록은 **설정 → 로그인 기록** 에 남아요.

### 비밀번호를 잊었을 때

1. 새 임시 비밀번호를 비밀 설정값으로 넣어요.

```bash
npx supabase secrets set ADMIN_INITIAL_PASSWORD="새-임시-비밀번호"
```

2. Supabase 대시보드 → **SQL Editor** 에서 아래 한 줄 실행 (저장된 비밀번호를 지워요)

```sql
update public.settings set admin_password_hash = null;
```

3. `/admin` 에서 새 임시 비밀번호로 로그인 → **설정 → 비밀번호 바꾸기**

### 매니저 코드 (선택)

**설정 → 매니저 코드 만들기** 를 누르면 `M-XXXX-XXXX` 코드가 **한 번만** 보여요. 매니저에게 전달하세요.
매니저는 사연 보기, 별표, 다음 사연 뽑기, OBS 카드 조작, 방송 시작·읽기 시작만 할 수 있고, 승인/반려, 후기 승인, 방송 결과 공개, 다시보기 링크 입력, 황금 동물 지급, 삭제, 설정은 못 해요. **끄기** 를 누르면 매니저 로그인이 모두 풀려요.

## 8. OBS 방송 카드 넣기

1. 관리자 페이지 → **OBS 카드** → **새 키 만들기**
2. 나온 주소(`https://사이트주소/obs?key=...`)를 **복사**
3. OBS → 소스 목록 **+** → **브라우저** → 새로 만들기
   - **URL**: 복사한 주소
   - **너비 1920, 높이 1080**
   - 사용자 지정 CSS 는 비워두세요 (배경은 이미 투명해요)
4. 관리자 페이지 **방송** 화면에서 **다음 사연 뽑기**, **카드 보이기/숨기기**, **본문 넘기기**, **고민 동물 공개** 를 누르면 2초 안에 방송 화면이 바뀌어요.

> 방송 화면에는 다웅이 **승인한 사연만** 열려요. 이름(공개 방식 반영), 나이·성별, 한 줄 요약, 감정 우표, 읽어줄 목소리와 **사연 본문**이 나오고, 길면 본문 넘기기 버튼으로 다음 쪽을 보여줘요.
> 주소가 유출됐다면 **새 키 만들기** 를 누르세요. 예전 주소는 바로 막히고, OBS 에 새 주소를 다시 넣으면 돼요.

## 9. 운영하면서 알아둘 것

- **사이트 흐름**: 사연 제출 → 그 자리에서 고민 동물 결과 → 관리자 **검토 대기** 에서 승인/반려 → 승인된 사연은 **방송 대기 목록**에 쌓임 → 방송을 켜면 **방송 시작** → **다음 사연 뽑기** 로 OBS 에 열고 **읽기 시작** → 방송 후 **오늘 방송 정리** 에서 다시보기 주소 붙여넣기 → **결과 공개** → 사연자가 결과 카드에서 상담 후기 → 승인한 후기는 첫 화면 **후기 벽**.
- **방송 후 정리 방법**: [방송-후-정리.md](방송-후-정리.md) 에 단계별로 정리해 두었어요.
- **고민 동물 도감 / 황금 동물**: 로그인한 사연자의 사연이 방송에서 읽혀 결과가 공개되면 고민 동물이 도감에 모여요. 이때 1% 확률로 황금 동물이 나오고, 인증하면 구독권을 줘요 (관리자 **황금 동물** 메뉴에서 코드 확인 후 "지급 완료").
- **자동 공개**: 설정한 기간(기본 14일) 동안 방송에서 못 읽은 사연은 사연자에게 "사연은 잘 받았어요. 다음 방송 후보에 남아 있어요" 안내가 보여요. "확인 필요" 사연은 빼요.
- **다음 사연 순서**: 가장 오래전에 도착한 날짜의 사연이 먼저예요. 그 날짜에 사연이 여러 개면 그 사연들끼리 룰렛을 돌려요. 못 읽은 사연은 다음 방송 때 그대로 이어져요.
- **반려**: 보낸 사람에게는 "이번엔 방송에 소개되지 않아요" 라고만 보이고, 이유는 보이지 않아요. 고민 동물 결과는 그대로 볼 수 있어요.
- **AI 사용량**: **통계** 에서 오늘/이번 달 호출 수를 볼 수 있어요. 호출 수 제한은 걸려 있지 않아요. 대략 사연 1개당 1회(형식이 틀리면 1회 더), 관리자가 "다시 만들기"를 누르면 1회예요.
- **AI 가 실패하면**: 사연 제출은 항상 성공하고, 고민 동물은 기본 동물 16종 중 하나로 정해져요. 관리자 상세 화면에 "AI 실패, 기본 동물 사용 중" 이 보이면 **다시 만들기** 를 누르세요.
- **Supabase 무료 플랜 일시정지**: 7일 동안 아무도 접속하지 않으면 프로젝트가 잠들어요. 대시보드에서 **Restore** 를 누르면 다시 켜져요. 매주 방송하면 거의 일어나지 않아요.
- **도배 방지**: 같은 기기/네트워크에서 10분에 3개, 하루 10개까지 낼 수 있어요. 사연 조회 비밀 코드를 5번 틀리면 10분 동안 막혀요.
- **백업**: 관리자 **설정 → CSV 내보내기** 로 모든 사연을 엑셀 파일로 받을 수 있어요.

## 10. 새 사연함 추가하기 (예: 환불원정대)

사연은 모두 `box_id`(사연함 종류)를 가지고 있고, 단계 구성(종류, 고민 틀, 우표, 목소리 등)은 `supabase/functions/_shared/boxes.ts` 한 파일에 모여 있어요.

1. `boxes.ts` 에 `GOMIN` 처럼 새 설정(`REFUND` 등)을 만들고 `BOXES` 에 추가
2. DB 에 한 줄 추가: `insert into public.boxes (id, name) values ('refund', '환불원정대');`
3. 사연 쓰기 화면(`web/src/pages/Write.tsx`)은 지금 고민 사연함 설정을 읽고 있어서, 새 사연함용 주소(예: `/refund/write`)를 연결하는 작업이 조금 필요해요. 서버(제출 검사, 접수번호, 관리자 목록)는 이미 사연함별로 나뉘어 동작해요.

## 11. (개발자용) 내 컴퓨터에서 띄워보기

Docker 가 필요해요.

